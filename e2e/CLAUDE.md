# E2E Rules

Priorities, in order: **Proof** (if green, the covered flows work against a production-shaped stack) > **No flakes** (designed for determinism; survives a saturated machine) > **Enforcement** (most rules carry a machine check; the rung column says which do not) > **Speed**.

**Meta-rule: a rule that isn't enforced isn't a rule.** Every rule below cites its enforcement. Saturation resilience is not a separate test — it is the emergent result of the No-flakes rules (no wall-clock anything, gate on app state, and fixed budgets sized for the saturated case). The worker count stays at the host's configured count, and saturation at that count is fixed by hardening the saturated resource (`docs/DECISIONS.md` §Tooling, process and documentation).

---

## Enforcement ladder

Attach every rule to the **highest rung achievable**. Descend only when the rung above is impossible. Rungs 5 and 6 are the tiers with no merge-gating enforcement — always-on reporting, documentation, review, or a mechanism that exists but does not run in CI; minimize both.

| Rung | Mechanism                 | Caught     | Blocks               |
| ---- | ------------------------- | ---------- | -------------------- |
| 1    | type system               | edit/build | build                |
| 2    | lint (pre-push + CI)      | pre-merge  | merge                |
| 3    | CI gate / contract test   | pre-merge  | merge/deploy         |
| 4    | runtime auto-fail fixture | during run | the test             |
| 5    | always-on reporting       | every run  | nothing (visible)    |
| 6    | doc + review checklist    | review     | nothing (discipline) |

**Enforcement tags** are the grammar `docs/CODE-RULES.md` §Enforcement states; every backticked token in an Enforcement cell is one of them. A prose mechanism says in its own cell that it gates nothing, because plain text is the shape a human sweep of this file misses worst.

## Pillar 2 — No flakes

Designed for determinism — app-emitted signals, no arbitrary waits — so the root causes of saturation flake are removed rather than tested for. Retries are configured as a backstop that no spec may rely on; `e2e:fast` and `e2e:stress` run at zero.

| #    | Rule                                                                                                                                                 | Enforcement                                                                                                                                                                                                                       | Rung  |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| 2.1  | No wall-clock waits, anywhere                                                                                                                        | `lint:playwright/no-wait-for-timeout` · `lint:playwright/no-networkidle` · `lint:no-restricted-syntax(setTimeout/setInterval)`                                                                                                    | 2     |
| 2.2  | Wait only on app-emitted readiness signals; signals are typed and contract-tested                                                                    | `type:TEST_SIGNALS` · `test:contracts/signals` · prefer signals over other waits `doc`                                                                                                                                            | 1/3/6 |
| 2.3  | Timeouts are fixed named budgets from one module; no inline literals, no runtime scaling                                                             | `lint:no-restricted-syntax(numeric timeout:)` · `type:TIMEOUTS`                                                                                                                                                                   | 2     |
| 2.4  | Control time, randomness, locale, timezone                                                                                                           | `config:timezoneId=UTC` · `config:locale` · `lint:no-restricted-syntax(Math.random, bare new Date())` · page.clock when time-dependent `doc`                                                                                      | 2/3/6 |

## Pillar 4 — Speed

**`pnpm e2e` and `pnpm e2e:stress` are the two scripts that run every test.** Every other script
narrows, and what it runs follows from what the invocation asks for, never from a spec being quietly
skipped by name. Speed comes from not re-proving engine-independent behaviour across the six matrix
projects, which between them run three engines — never from running a subset. A project selection
that drops a spec is a coverage hole wearing a performance win's clothes.

| 4.3 | Right-sized, parallel-safe worker counts                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | `config:workers`                                                                                                                                                | 3    |
| 4.4 | No redundant waiting                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | `lint:no-restricted-syntax(numeric timeout:)`                                                                                                                   | 2    |
| 4.5 | Every spec declares **engine coverage** (`engine-matrix` / `engine-any` / `engine-pinned` / `engine-fixed`) and **form factor** (`desktop` / `mobile` / `either`). Neither defaults — a default silently narrows coverage for whoever forgets. The project set is derived from the two: `engine-matrix` runs every engine for its form factor; `engine-any` runs on exactly one project **chosen from those selected in this run**, so a single-project invocation carries those specs rather than skipping them; `engine-pinned` names the one engine that can run it and is **never substituted** — a run holding that spec's form factor but not that engine refuses at config load rather than handing the spec to an engine that cannot run it; `engine-fixed` is for a spec whose plane fixes the engine — it elects no carrier and the engine projects never collect it, so it is valid only inside a plane's own testDir | `type:MatrixDeclaration` · `lint:browser-matrix/matrix-declaration` · `config:grepInvert`                                                                       | 1/2  |
| 4.6 | `engine-any` and `engine-pinned` each carry a one-line reason. ## Debugging

`e2e/report/<latest>/` is the single source of truth when tests fail — use `/debug-e2e` to investigate.
